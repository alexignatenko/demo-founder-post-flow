# Истории из встреч

Цель — копилка рабочих историй, из которых потом пишется контент. История — конкретный эпизод: люди (роли), ситуация, напряжение, поворот. Общие советы, договорённости и статусы задач — не истории.

## Файлы

- `контент/истории/` — по файлу на историю: `YYYY-MM-DD_slug.md` (дата встречи, slug латиницей по смыслу).
- `контент/истории/INDEX.md` — таблица всех историй, пересобирается после каждого изменения командой `python3 .agents/skills/meeting-stories/build_index.py` (читает frontmatter карточек, руками не править).
- `контент/истории/ТЕМЫ.md` — фиксированный словарь тем и аудиторий. Новую тему добавлять только осознанно и сразу в словарь.
- `контент/истории/обработанные_встречи.md` — реестр разобранных встреч (папка встречи → дата разбора → сколько историй). Перед разбором проверять: уже разобранные встречи не разбирать повторно, если пользователь прямо не попросил.

## 1. Извлечь истории за период

1. Найти встречи: папки `встречи/wispr/` с датой в названии внутри периода. Пропустить уже обработанные.
2. Читать **транскрипт целиком**, не только саммари: саммари теряет истории. Саммари можно использовать для быстрой сортировки — чисто операционные синки (статусы задач, доступы, оплаты) без эпизодов пропускать, но отмечать в реестре с 0.
3. **Проверять говорящего по смыслу.** Wispr путает спикеров (бывало, что реплики друга подписаны как реплики Алекса, и саммари повторяло ошибку). Кто рассказал историю — определять по контексту («я на 12 лет старше», «мне подогнали слот»), а не по подписи.
4. Отобрать истории, которые проходят **фильтр аудитории** (ниже).
5. Обезличить (ниже), оформить карточку, сохранить файл.
6. Обновить `INDEX.md` и реестр встреч.
7. В чат — список новых историй (название + для кого + одна строка сути) и список встреч без историй. Полный текст карточек в чат не выводить, если не попросили.

### Фильтр аудитории

Читатели: **фаундер / собственник**, **руководитель маркетинга или закупки трафика**, **аналитик** (в т.ч. начинающий, ищущий работу). История проходит, если хотя бы один из них узнает в ней себя или она может изменить его решение про деньги, данные, трафик, найм, продажи, процессы, AI в работе.

Не проходят: личная жизнь, отношения, семья, здоровье, хобби, спорт, практики, путешествия, дружеские байки — даже яркие. Чужие истории третьих лиц, которые не на встрече, — только если они рабочие и полностью обезличены.

### Обезличивание (жёстко)

В карточке **нет**: имён и фамилий (включая Алекса — он «я»), названий компаний, брендов, продуктов клиентов, мероприятий и конференций, городов/стран, если они узнаваемы в связке с историей, ссылок, никнеймов.

Заменять на роль и тип: «менти-аналитик», «фаундер iGaming-проекта», «маркетплейс цифровых товаров», «партнёр по консалтингу», «крупная конференция по аналитике», «американский SaaS по передаче конверсий». Цифры оставлять, если по ним нельзя вычислить компанию. Цитаты — только очищенные от имён, можно слегка сократить, смысл не менять.

Единственное место для идентификаторов — поле `source` во frontmatter (папка встречи и таймкод) — служебное, в контент не идёт.

Если история сильная, но без согласия человека её публиковать нельзя (личный рабочий опыт друга, конфликт с работодателем) — ставить `consent: нужно согласие`.

### Название истории

Из названия должно быть понятно, о чём речь и почему это интересно: **ситуация/боль в словах читателя + парадокс или неожиданный поворот**. Это не хук поста, но с крючком. Без имён и без кликбейта, который история не подтверждает.

Хорошо:
- «Сотни тысяч на трафик, ни одной измеримой связки — а деньги пошли, когда маркетинг выключили»
- «Рекламный кабинет видит в 10 раз меньше покупок — и учится не на тех людях»
- «Я оценивал работу в 2 тысячи долларов. Рынок продаёт то же самое за 200 тысяч в год»

Плохо: «История про iGaming», «Встреча с фаундером», «Важность аналитики».

### Карточка

```markdown
---
title: "<название по формуле выше>"
date: YYYY-MM-DD            # дата встречи
audience: [фаундер, маркетинг, аналитик]   # 1–3 из словаря
topics: [атрибуция-и-трекинг, ...]          # 1–3 из ТЕМЫ.md
storyteller: я | собеседник | третье лицо   # кто прожил историю
status: новая               # новая | в работе | использована | отклонена
used_in: []                 # пути/ссылки на посты, где использована
consent: не нужно           # не нужно | нужно согласие
source: "встречи/wispr/<папка> @ MM:SS"
---

**Ситуация.** Кто (роль), где (тип компании/контекста), что происходило — 2–4 предложения с цифрами.

**Проблема.** В чём напряжение или боль.

**Поворот.** Что оказалось не так, как казалось.

**Вывод.** Что из этого следует — одна-две фразы.

**К чему ведёт.** Последствия для читателя: что поменять в решениях, о чём это для фаундера/маркетинга/аналитика.

**Цитата.** «…» (обезличенная, с таймкодом в source)

**Оговорки.** (если есть) история из вторых рук, цифру проверить, нужна деталь у человека.
```

Без «силы истории», вариантов хуков и площадок — это решается при написании поста.

### INDEX.md

Таблица, по строке на историю, сортировка по дате (новые сверху):

```
| Дата | Название | Для кого | Темы | Статус | Файл |
```

Сверху — счётчики: всего, новых, использованных.

## 2. Найти истории

По запросу «найди истории для фаундеров про атрибуцию», «что есть про найм», «неиспользованные про AI-агентов»: читать frontmatter всех карточек (и тексты, если нужен смысловой поиск), фильтровать по `audience`, `topics`, `status`, дате и смыслу. По умолчанию показывать только `новая` и `в работе`. Ответ — список: название, для кого, одна строка сути, файл.

## 3. Взять историю в пост

По «возьми историю X в пост»: прочитать карточку, писать пост по нужному голосу (`контент/voice_guide_expert.md` для LinkedIn/блога, Threads-гайд для Threads и т.д.) с учётом `no-ai-slop`. Обезличивание сохраняется и в посте. После того как пользователь принял пост — `status: использована`, путь/ссылку в `used_in`, пересобрать `INDEX.md`.
